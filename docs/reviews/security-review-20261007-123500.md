### Low

#### [F2] expires_in from the token endpoint has no lower bound — a 0 / tiny value makes every request refresh
- **File:** `Scripts/_mcp_oauth.py:551`
- **OWASP:** A04:2021 — Insecure Design
- **CWE:** CWE-1284
- **CVSS:** not recorded (LOW)
- **Confidence:** MEDIUM
- **Confirmed trace:** token endpoint answer body → `_oauth_parse_token_response` (`_mcp_oauth.py:548-555`, accepts any int >= 0, `earliest_refresh_at = now`) → persisted `expires_at` → `_oauth_token_due` (`_mcp_oauth.py:702`)
- **Evidence:**
  ```python
  elif isinstance(expires_in, bool) or not isinstance(expires_in, int) or expires_in < 0:
      raise OAuthError("invalid_response")
  else:
      expires_at = now + expires_in
  return {..., "expires_at": expires_at, ..., "earliest_refresh_at": now}
  ```
- **Impact:** a misbehaving or hostile (semi-trusted) token endpoint answering `expires_in` 0 or below the refresh skew makes every inference request due for refresh — a refresh-POST storm and refresh-token rotation churn (rate limiting / abuse flags on the account).
- **Remediation:**
  ```python
  # clamp expires_in to a sane floor, or give earliest_refresh_at a minimum
  # distance from now so a short lifetime cannot force one refresh per request
  ```

#### [F9] json.loads with no integer-literal bound on bare Python 3.9 — quadratic int conversion on every JSON parse path
- **File:** `Scripts/llm-router.py:344` (also `Scripts/_mcp_oauth.py:474`)
- **OWASP:** A04:2021 — Insecure Design
- **CWE:** CWE-1284 (CWE-407)
- **CVSS:** not recorded (LOW)
- **Confidence:** MEDIUM
- **Confirmed trace:** client POST body (up to 32 MiB) / upstream Responses SSE event (16 MiB) / token endpoint body (1 MiB) → `_rt_loads` (`llm-router.py:344`) / `_oauth_json_object` (`_mcp_oauth.py:474`) → `json.loads` int conversion with no `parse_int` hook
- **Evidence:**
  ```python
  return json.loads(text, parse_constant=_rt_no_constant, parse_float=_rt_finite_float)
  ...
  obj = json.loads(body, object_pairs_hook=_oauth_no_duplicate_keys, parse_constant=_oauth_no_constant)
  ```
- **Impact:** on Python 3.9.6 (no `int_max_str_digits`) a multi-megabyte digit string costs quadratic CPU inside `json.loads` before any range check, pinning a handler thread.
- **Remediation:**
  ```python
  # parse_int hook: refuse a literal longer than 4300 chars with ValueError
  # (already mapped to the malformed-JSON path) in _rt_loads and _oauth_json_object;
  # or declare it (a roadmap item already exists for mcp-proxy)
  ```

#### [F18] _RtMessageCollector accumulates text/thinking deltas with `+=` on a dict item — quadratic
- **File:** `Scripts/llm-router.py:1934` (also `:1944`)
- **OWASP:** A04:2021 — Insecure Design
- **CWE:** CWE-407
- **CVSS:** not recorded (LOW)
- **Confidence:** MEDIUM
- **Confirmed trace:** upstream Responses SSE body on the non-stream path (`ResponsesAdapter.json_response`) → `ResponsesStreamTranslator.feed` → `_on_text` / `_on_summary_delta` → `_RtMessageCollector.text` / `.thinking`
- **Evidence:**
  ```python
  self.content[-1]["text"] += delta
  ...
  self.content[-1]["thinking"] += delta
  ```
- **Impact:** no CPython in-place concat optimisation applies to a dict item; a 2xx body up to the 64 MiB upstream limit split into very many tiny delta events makes the router copy the growing string each time (O(n^2) CPU/memory). Upstream is semi-trusted; the stream path is linear.
- **Remediation:**
  ```python
  # collect the deltas in a per-block list and "".join() once when the block closes
  ```

#### [F40] Router/login lost update — a running router's next rotation overwrites a fresh login on disk
- **File:** `Scripts/llm-router.py:5573` (merge `:1447`, digest change only logged `:1468`)
- **OWASP:** A04:2021 — Insecure Design
- **CWE:** CWE-362
- **CVSS:** not recorded (LOW)
- **Confidence:** HIGH
- **Confirmed trace:** `llm-router.py login` writes a new grant → running router `_refresh` still holds the old in-memory refresh token → `_rt_persist` (`:5573-5574`) → `_rt_config_update_oauth` → `_rt_config_merge` replaces `backends.<n>.oauth` wholesale (`:1447`); a changed disk digest is only logged (`:1468-1470`) → rename over the config
- **Evidence:**
  ```python
  if new_refresh != refresh or account != state.account_id:
      self._rt_persist(backend, self._persisted(state, new_refresh, account, got["expires_at"]))
  ...
  merged_entry["oauth"] = persisted
  ...
  if digest != expected_digest and not logged:
      log.info("config changed since load; merged backends.%s.oauth only", _log_value(backend))
  ```
- **Impact:** a user who re-logs in (switch account, or after revoking the old grant) while the router runs has the new grant silently overwritten on the router's next refresh; the router keeps acting as the old identity. The KD-20 flock serializes writes but does not detect the semantic conflict.
- **Remediation:**
  ```python
  # under the flock, compare the on-disk refresh_token with the one this refresh
  # started from; if it differs (and is not the dead refresh token) do not write,
  # raise ConfigConflict and let the token store _adopt the on-disk grant
  ```

#### [F47] --help epilog teaches putting the router auth_token on curl argv and into shell history
- **File:** `Scripts/llm-router.py:7417` (also `:7409`)
- **OWASP:** A05:2021 — Security Misconfiguration
- **CWE:** CWE-214 (CWE-532)
- **CVSS:** not recorded (LOW)
- **Confidence:** MEDIUM
- **Confirmed trace:** static `_RT_HELP_EPILOG` → argparse `--help` → operator copies the commands → token in process argv (`ps`) and in `~/.bash_history` / `~/.zsh_history`
- **Evidence:**
  ```text
  export ANTHROPIC_AUTH_TOKEN=<auth_token>           # sent as Authorization: Bearer
  ...
  curl -s -H "Authorization: Bearer <auth_token>" http://127.0.0.1:8082/v1/models
  ```
- **Impact:** the exact argv/history exposure the parser cites as the reason there is no `--config-json` (FR-11); with `--allow-remote` the auth_token is the only gate.
- **Remediation:**
  ```sh
  read -rs ANTHROPIC_AUTH_TOKEN && export ANTHROPIC_AUTH_TOKEN
  printf 'Authorization: Bearer %s\n' "$ANTHROPIC_AUTH_TOKEN" | curl -s -H @- http://127.0.0.1:8082/v1/models
  ```
