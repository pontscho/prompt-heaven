# tests/files — language fixtures for the semantic-navigation surface

These are **fixtures, not real code**. Nothing here is compiled, linked, shipped
or imported by the project. They exist so the compiler/LSP-accurate half of
`purity_call` can be exercised inside this repo, which is otherwise Python and
Markdown only.

## Why they exist

`mcp-clangd` and `mcp-luals` were unregistered as standalone MCP servers because
`purity_call` absorbed their semantic navigation. That claim needed a way to be
tested. Before these fixtures the repo contained no C/C++ at all and only a few
throwaway `.lua` files under `.claude/tmp/`, so the absorption could only be
validated by switching to a different project.

## The `tf` prefix rule — do not break it

**Every symbol, type, macro and module name here starts with `tf`** (`tf_vec_add`,
`TF_VEC_DIM`, `tfMathlib`, …). That is deliberate: a repo-wide search for a real
symbol must never match this directory, and a headless eval that greps the repo
must not pick these up as if they were project code. If you add a fixture, keep
the prefix.

## Layout

```
c/    tf_math.h      declarations: macro, enum, struct, three functions
      tf_math.c      the definitions
      tf_main.c      call sites, so find_references has several hits to find
      tf_broken.c    deliberate type error, for the diagnostics path
lua/  tf_mathlib.lua module table with functions and fields
      tf_consumer.lua requires the module and calls into it
      tf_broken.lua  deliberate defect, for the diagnostics path
```

`tf_broken.*` are **meant to be broken**. Do not "fix" them; a test asserts that
the LSP reports a problem in them. They are never part of a build.

## sbx_restrict/ — not an LSP fixture

```
sbx_restrict/ probe_read.py   L1-L8, L11: reads/stat/exec denied, "/" listing, ACL vs flag writes
              probe_exec.sh   L9: bash subshell, /bin/sh, `kill $!` of a background job
              probe_node.js   L10: require('os') and a write in the cwd
              probe_depth.py  L12: the 100-level depth cap (M0:9)
```

In-sandbox probes for `tests/test_sbx_restrict.py` group L (live restricted
Seatbelt, macOS). The suite copies each probe into a fresh write scope under
`.claude/tmp/test_sbx_restrict/` and runs it there under a restricted `sbx`,
so no repo path is ever granted. Each probe is stdlib only, opens no network
connection and prints ONE JSON line: per attempt, `"ok"` or the errno name.
It never prints a byte of what it read. Run unsandboxed, no attempt answers
`EPERM`, and `probe_depth.py` reports `"ok"` for every form. A missing path
still answers `ENOENT`. `probe_depth.py` leaves its chains in place for the
caller to remove.
The file names are the plan's (Step 6); every symbol inside carries the `tf`
prefix.

## mcp_sandbox/ — not an LSP fixture

```
mcp_sandbox/ config.json.tmpl        every runner config: {sbx} {work_root} {interpreters}
             fake_sbx.py.tmpl        I11: real sbx, except an engine failure after `spawned`
             escape/e01..e34_*.py    group E: one escape probe per row (python3)
             escape/e16_env.sh .js   E16: the same env-keys probe in bash and node
             escape/e34_setuid.sh    E34: setuid binaries through /bin/sh -c (bash)
```

Read by `tests/test_mcp_sandbox.py`. `config.json.tmpl` holds three UNQUOTED
placeholders where a JSON value goes, filled ONLY with
`text.replace(placeholder, json.dumps(value))` (never `str.format`; M0:13);
the rendered file lands mode 0600 under `.claude/tmp/test_mcp_sandbox/`.
`fake_sbx.py.tmpl` has two tokens, `@REAL_SBX@` and `@TRIGGER_DIR@`, replaced
with `repr()` of absolute paths. The `escape/` probes are sent as a run's
entry file and run INSIDE the sandbox (group E, live, macOS); the suite also
runs each one OUTSIDE any sandbox as the row's positive control. Each probe
is stdlib only, opens no network except the test's own loopback listeners
(E6, E7), never prints a byte of what it read, and prints ONE JSON line (E11
prints it on stderr, its stdout being the flood). Probes that write leave
nothing outside their cwd; the runner removes the workdir.

## mcp_skill/ — not an LSP fixture

```
mcp_skill/ stub_runner.py   a canned mcp-sandbox stand-in: the runner behind a test mcp-proxy --http
```

Read by `tests/test_mcp_skill.py` groups I and J. It is run as `__main__` as
the ONE stdio child of a test `mcp-proxy.py --http`, so mcp-skill's runner
HTTP client talks to a real proxy over Streamable HTTP while the results are
scripted here; nothing imports it. It is stdlib only (Python 3.9) and speaks
newline-delimited JSON-RPC: `initialize`, `ping`, `tools/list` (one tool,
`sandbox_call`) and `tools/call`. Its answers follow the runner's contract: a
result is one JSON text block plus the same object as `structuredContent`,
and a refusal is `isError` with `{"error": {...}}`, never a JSON-RPC error.
Each `run_script` answer is picked by `--mode`, or per call by the first line
of `--mode-file`, so one proxy serves several rows: `normal`, `echo` (the
request's files and encodings, metadata only), `hostile` (every class the
sanitizer must drop, plus a forged frame end marker), `busy`, `unavailable`,
`sleep` (the SSE keepalive row), `timeout`, `big` and `rpc_error`. With
`--state-dir` it appends one metadata-only JSON line per received message to
`stub_runner.events.jsonl` (0600, `O_APPEND`) and its pid to
`stub_runner.pids`, the evidence behind a row's "the runner saw NO request".
It never records a file's content, and it exits 0 at stdin EOF. The file
name is the plan's (Step 18); every symbol inside carries the `tf` prefix,
and its flags and modes are documented in its own docstring.

## gpu_router/ — not an LSP fixture

```
gpu_router/ tf_stub_sd.py   the adversarial stub sd-server child for tests/test_gpu_router.py
gpu_router/ tf_stub_llm.py  the adversarial stub inferNO-style LLM child for tests/test_gpu_router.py
```

A stdlib-only (Python 3.9) loopback HTTP/1.1 stand-in for stable-diffusion.cpp
`sd-server`, run as `__main__` as a model's `bin` by `tests/test_gpu_router.py`;
nothing imports it. It serves the four synchronous image routes with canned
sd-shaped JSON carrying the SHA-256 of the request body it received, answers
`GET /` with the readiness status gpu-router expects, and crashes, stalls, keeps
generating, spawns a grandchild or fails its first N starts on command, so the
suite can drive switching, retries, the restart budget and the kill ladder.
With `--state-dir` it records one metadata-only JSON line per event, its pids
and the exact POST bodies (0600) under the suite's `.claude/tmp/test_gpu_router/`
run directory: the evidence behind the byte-exact relay rows. It never prints
a request body, a header value or an environment value. Every symbol inside
carries the `tf` prefix, and its routes, state files and flags are documented
in its own docstring.

`tf_stub_llm.py` is the second stub: one inferNO-style process that serves three
model ids on one loopback port (`GET /v1/models`, `GET /health`, and
`POST /v1/chat/completions`, `/v1/messages`, `/v1/embeddings`, `/v1/rerank` with
canned JSON or an SSE stream). It does not listen while it "loads"
(`--start-delay`), can answer 404 on `/v1/models` after the bind
(`--ready-404-for`), stalls, streams slowly (`--event-delay`, `--think-gap`,
`--event-bytes` to flood), drops a stream (`--drop-after`), answers a fixed
error status (`--answer-status`) or adds response headers (`--head-extra`,
`--head-pad` for an oversize head) on command. Its `.events.jsonl` ledger records `start` (pid), `request`
(body SHA, header names, the two `anthropic-*` values), `client_gone` and
`closed_by_peer`. Same rules as the sd stub: metadata only, no body or secret on
any output, every symbol prefixed `tf`.

## Notes on the toolchain

- No `compile_commands.json` is committed. It is inherently machine-specific and
  would be stale for anyone else. These translation units are plain C99 with a
  local `#include`, which clangd handles on its fallback flags. If a future test
  needs exact flags, generate the file at test time rather than committing one.
- CUDA fixtures are deliberately absent: `nvcc` is not installed on the current
  machine, so a `.cu` fixture could not be honestly verified here.
- The Lua files rely on `lua-language-server` defaults; no `.luarc.json` is
  committed for the same staleness reason.
